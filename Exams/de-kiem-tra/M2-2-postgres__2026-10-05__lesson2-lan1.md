## Schema và dữ liệu dùng chung

Đây là schema giả định của đề, **không khẳng định đã chạy trong `shopcore`**. Giả sử không có trigger, rule hay transaction khác đang can thiệp.

```sql
CREATE TABLE categories (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE products (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sku TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    price NUMERIC(12,2) NOT NULL CHECK (price > 0),
    category_id BIGINT REFERENCES categories(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    attributes JSONB
);
```

**categories**

| id | name |
|---:|---|
| 1 | Books |
| 2 | Electronics |

**products**

| id | sku | name | price | category_id |
|---:|---|---|---:|---:|
| 10 | BK-01 | Java Book | 120.00 | 1 |
| 11 | EL-01 | Mouse | 300.00 | 2 |
| 12 | BK-02 | SQL Book | 80.00 | 1 |

## Câu 6 - Trùng SKU: `DO NOTHING` có nghĩa gì? (5đ)

```sql
INSERT INTO products (sku, name, price, category_id)
VALUES ('BK-01', 'Another Java Book', 90.00, 1)
ON CONFLICT (sku) DO NOTHING
RETURNING id;
```

Có dòng mới không? `RETURNING` có tự trả id của Product `BK-01` cũ không? Nếu yêu cầu nghiệp vụ là **báo lỗi SKU đã tồn tại**, có nên dùng `DO NOTHING` ở đây không? `DO NOTHING` có bỏ qua lỗi giá âm/FK sai không?

**Trả lời:**
sẽ không có dòng mới vì đã bị trùng sku , nó sẽ trả về INSERT 0 , và nó sẽ không tự trả về id của product cũ , nếu nghiệp vụ có báo lỗi là SKU đã tồn tại thì không nên xài DO NOTHING mà nên để constraint UNIQUE xử lý và ở globalEXceptionhandler nó sẽ giải quyết , `DO NOTHING` có bỏ qua lỗi giá âm/FK sai vì nó chỉ khi gặp confliuct thì nó sẽ dônthing còn sai CHECK , FK thì k xử lý dc

## Câu 7 - Phân biệt dữ liệu trả về và lỗi constraint (5đ)

Hai lệnh **độc lập**:

```sql
-- A
UPDATE products
SET price = price + 10
WHERE id = 11
RETURNING id, price;

-- B
UPDATE products
SET price = -20
WHERE id = 11
RETURNING id, price;
```

Lệnh A trả gì trong `RETURNING`? Lệnh B có thể trả một dòng thành công với giá `-20` không? Phân biệt rõ `UPDATE 0` với lệnh bị constraint từ chối.

**Trả lời:**
lệnh A sẽ trả về id là 11 ,price là 310 , lệnh B không trả về dòng thành công với giá -20 vì là nó bị vi phạm CHECK giá ấm , UPDATED 0 có nghĩa là không có dòngn ào được áp dụng update ,  UPDATE 0 khi mà nó không vy phạm constrain hay là bâts kì cái gì nhưng mà k có dòng nào được thay đổi thì là UPDATE 0.  ví dụ như update Id k tồn tại ,category k tồn tại , còn constraint bị từ chối là vì k đúng với quy tắc của dữ liieuej đó , vi phạm tính đúng đắn của dữ liệu , SET mà nếu không tồn tại id thì sẽ là lỗi FK , còn where thì sẽ dc UPDATE 0
