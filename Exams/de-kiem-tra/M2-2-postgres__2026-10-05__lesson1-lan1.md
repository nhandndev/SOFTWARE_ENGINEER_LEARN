## Dữ liệu và schema dùng chung

Đây là dữ liệu giả định cho đề, **không phải schema đã chạy trên `shopcore`**:

```sql
CREATE TABLE categories (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE products (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sku TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    price NUMERIC(12,2) NOT NULL CHECK (price > 0),
    category_id BIGINT REFERENCES categories(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    attributes JSONB
);
```

Giả sử `categories` có `(1, 'Books')`, `(2, 'Electronics')`; `products` có một dòng với `sku='BK-01'`, `price=120.00`, `category_id=1`. Mỗi tình huống ở dưới **độc lập**, không tự cộng dồn dữ liệu giữa các câu.

## Câu 2 - `IDENTITY` khác `PRIMARY KEY` (5đ)

`id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`: phần nào **sinh** id khi không gửi id? Phần nào bảo đảm id **duy nhất, không NULL**? Nếu bỏ `PRIMARY KEY` mà giữ `IDENTITY`, có được khẳng định id chắc chắn không bao giờ trùng không? Vì sao?

**Trả lời:** GENERATED BY DEFAULT AS IDENTITY phần id sẽ sinh ra khi mà không có value thì nó sẽ được tự động gán giá trị của thg Postgre , bảo đảm duy nhất d là PRIMARY KEY , nếu bỏ PRIMARY KEY mà giữ IDNETITY thì không chắc chắn được là không bao giừo trugnf , vì thằng IDENTITY mục đích chỉ để khi mà không gắn value thì nó sẽ được tự khởi tạo giá trị , có trường hợp khác là 1 người nào đó vô tình set value trùng với cái cũ thì coi như là bị trùng , nên là cần phải có PRIMARY KEY . ## Câu 3 - Giá dương và `NULL` (5đ)

Với `price NUMERIC(12,2) NOT NULL CHECK (price > 0)`, lần lượt `price=100`, `price=0`, `price=-5`, `price=NULL` được nhận hay bị từ chối? Chỉ rõ constraint chặn. Nếu bỏ riêng `NOT NULL`, `price=NULL` sẽ thế nào với `CHECK (price > 0)` trong PostgreSQL?

**Trả lời:**

--- price =100 nhận , = 0 thì từ chối , -5 từ chối , = null từ chối , vì constraint chặn là Not nULL , chặn price <=0 và yêu cầu phải > 0 price = NULL thì không thể dùng `CHECK (price > 0) vì không thể dùng các phép so sánh với NULL , mà ta phải dùng NOT NULL . CHECK là dùng để chặn giá nếu có value và value đó phải > 0 , còn NOT NULL là chặn nó cấm cho NULL
