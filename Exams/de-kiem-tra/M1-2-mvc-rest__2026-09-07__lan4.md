## Câu 1 - Kể luồng request đầy đủ (5đ)

Client gọi:

```http
POST /api/products
Content-Type: application/json

{
  "sku": "KB-001",
  "name": "Keyboard",
  "price": 1500000,
  "categoryId": 1
}
```

Hãy kể request này đi qua các bước từ lúc vào server tới lúc client nhận response.

Cần có các ý:

- FilterChain.
- DispatcherServlet.
- HandlerMapping.
- HandlerAdapter.
- Argument Resolver/Jackson.
- Controller, Service, Repository.
- DTO request/response.
- ResponseEntity/ApiResponse.

**Trả lời:** Client gửi HTTP request gồm method, URL, header và body JSON.
Tomcat nhận request và tạo HttpServletRequest/HttpServletResponse.
Request đi qua FilterChain, ví dụ security, CORS, auth.
Sau đó vào DispatcherServlet, là trung tâm điều phối của Spring MVC.

DispatcherServlet dùng HandlerMapping để tìm Controller method phù hợp với POST /api/products.
Nếu có interceptor thì preHandle chạy trước.
Sau đó HandlerAdapter chịu trách nhiệm gọi method đó.
Trước khi gọi Controller, Spring dùng argument resolver để bind path/query/body.
Với @RequestBody, Jackson convert JSON thành CreateProductRequest.
Nếu có @Valid thì validation kiểm tra DTO.

Controller nhận DTO đã bind sẵn, chỉ gọi Service.
Service xử lý business rule như check SKU, check Category, check price.
Service gọi Repository để lấy/lưu dữ liệu.
Repository giao tiếp với data store.
Sau đó Service map Product/Entity sang ProductResponse.
Controller bọc ProductResponse bằng ApiResponse/ResponseEntity, set status như 201 Created.
Cuối cùng Jackson convert response object thành JSON và trả về client.
- DTO request/response.
- ResponseEntity/ApiResponse.
thì controller nó là API mỏng để giao tiếp và truyền nghipeej vụ xuống cho service , thì service sẽ xử lý nghiệp vụ và return lại response , có thể nó sẽ dùng repository , repository là nó sẽ xử lý phần giao tiếp với database , xử lý data , thì lúc mà nhận request và response thì cần phải có DTO , đây là biên object dùng để che những field không cần thiết , tách tạch API với model/entity , dùng để cấm cho client chỉnh sửa field k cần thiết và thường thì tôi sẽ dùng DTO . ResponseEntity thì thứ mà controller sẽ trả về và nó sẽ bọc APiResponse hoặc là PagingResponse tuỳ vào cái method đó

## Câu 11 - Code mini AppException (10đ)

Viết pseudo-code hoặc Java ngắn cho case `getById`.

Yêu cầu:

- Controller endpoint `GET /api/products/{id}`.
- Service gọi repository.
- Nếu không có Product thì throw `AppException(ErrorCode.PRODUCT_NOT_FOUND)`.
- Nếu có thì map sang `ProductResponse`.
- Handler bắt `AppException` và trả `ApiErrorResponse`.

Không cần code compile 100%, nhưng phải đúng luồng và đúng trách nhiệm.

**Trả lời:**
RestController
@RequestMapping("/api/products")
public class ProductController {
    private final ProductService productService;
    thêm cái constrcutor ở đây nữa hoặc dùng @@RequiredArgsConstructor
    @GetMapping("/{id}")
    public ResponseEntity<ApiResponse<ProductResponse>> getById(
            @PathVariable Long id) {
        ProductResponse result = productService.getById(id);
        return ResponseEntity.ok(ApiResponse.success(result));
    }
}
```

```java
@Service
public class ProductService {
    private final ProductRepository productRepository;

    public ProductResponse getById(Long id) {
        Product product = productRepository.findById(id)
                .orElseThrow(() ->
                        new AppException(ErrorCode.PRODUCT_NOT_FOUND));

        return ProductResponse.builder()
                .id(product.getId())
                .sku(product.getSku())
                .name(product.getName())
                .price(product.getPrice())
                .categoryId(product.getCategoryId())
                .build();
    }
}
```

```java
@ExceptionHandler(AppException.class)
public ResponseEntity<ApiErrorResponse> handleAppException(AppException e) {
    ErrorCode errorCode = e.getErrorCode();
    ApiErrorResponse body = ApiErrorResponse.builder()
            .code(errorCode.getCode())
            .message(errorCode.getMessage())
            .build();
    return ResponseEntity.status(errorCode.getHttpStatus()).body(body);
}
```



## Câu 12 - Câu chốt pass module (4đ)

Hãy trả lời bằng 5-8 dòng:

> Khi một request REST đi vào Spring Boot, lỗi có thể bị phát hiện ở những chỗ nào? Phân biệt lỗi mặc định của Spring/Jackson với lỗi business từ `AppException`.

**Trả lời:**
Các tầng phát hiện lỗi: Filter/Security (sai token/auth) $\to$ Jackson Converter (sai cú pháp JSON, sai kiểu dữ liệu) $\to$ Controller (@Valid vi phạm annotation) $\to$ Service (lỗi logic) $\to$ Database (lỗi ràng buộc toàn vẹn).Nguồn gốc phát sinh: Lỗi Spring/Jackson do framework tự động phát hiện và ném ra ở tầng hạ tầng/tiền xử lý; AppException do lập trình viên chủ động throw tại Service khi vi phạm logic.Bản chất lỗi: Lỗi Spring/Jackson mang tính kỹ thuật cú pháp (HttpMessageNotReadableException, MethodArgumentNotValidException); AppException mang tính nghiệp vụ domain (tài khoản đã tồn tại, không đủ số dư).Mã trạng thái (HTTP Status): Lỗi framework thường mặc định gán cứng (400, 405, 415); AppException linh hoạt ánh xạ theo từng ca nghiệp vụ cụ thể (400, 404, 409 Conflict, 422).Cấu trúc phản hồi (Response): Lỗi mặc định có format thô của Spring dễ lộ vết hệ thống; AppException được chuẩn hóa tập trung qua @RestControllerAdvice để trả về ErrorCode và message thân thiện cho client.
