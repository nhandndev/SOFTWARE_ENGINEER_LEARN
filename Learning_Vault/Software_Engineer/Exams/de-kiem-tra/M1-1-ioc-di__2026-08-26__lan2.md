## Phần I - Lý thuyết ngắn `(6 câu × 3đ = 18đ)`

### Câu 1. Bean lifecycle cơ bản trong Spring gồm những bước nào từ lúc tạo bean đến lúc app tắt? `(3đ)`

**Trả lời:** gồm đầu tiên là Application context  bắt đầu , sau dó spring tạo instance , sau đó là Dependenci injection , sau đó là init , sau đó là ready chuẩn bị cho application dùng , sau đó là dùng , dùng xong rồi shutdown xong destroy


### Câu 2. `@PostConstruct` là gì? Nó chạy khi nào? Có phải dùng để xóa bean không? `(3đ)`

**Trả lời:**PostContruct là Bean LifeCycle , nó dùng để sau khi mà bean tạo xong và đã tiêm dependency xong , nó k dùng để xoá mà để kích hoạt


### Câu 3. `@PreDestroy` là gì? Nó chạy khi nào? Dùng cho việc gì? `(3đ)`

**Trả lời:** là bena lifecycle , dùng trước khi mà app shutodwn và nó sẽ xoá bean 


### Câu 4. `InitializingBean.afterPropertiesSet()` thuộc nhóm init hay destroy? Nó giống annotation nào hơn? `(3đ)`

**Trả lời:**thuộc nhóm init , nó giongos annonation @PostConstructor


### Câu 5. Phân biệt nhanh `@Component` và `@Bean`. Khi nào dùng mỗi cái? `(3đ)`

**Trả lời:** @Compontent là dùng trên class và do mình viết  , @Bean dùng trên method  thường là dùng từ dependency được import từ ngoài , @Compotent là strereoType như @Service , @Repository , @Bean là dùng cho các class bên ngoài , giống như clock thì ta import nên là sẽ dùng @Configuration và @Bean


### Câu 6. Spring singleton scope khác prototype scope ở đâu? `(3đ)`

**Trả lời:** Singleton scope là chỉ có 1 instance tạo ra từ bean trong bean container , còn prototype là cho phép tạo instance mới mỗi lần request bean container

### Câu 7. Trong `shopcore`, phân loại các object sau nên dùng annotation/cách tạo bean nào: `ProductService`, `SkuGenerator`, `Clock`, `ObjectMapper`, `InMemoryProductRepository`. Giải thích ngắn. `(5đ)`

**Trả lời:** Product Service thì dùng @Service vì là bussiness service  , @SkuGenerator thì dùng @Component do mình viết, @Clock thì dùng bean do import từ class bên ngoài , @ObjectMapper thì dùng @bean do cũng được import từ class bên ngoài  , InmemmoryProductRepository thì dùng @Repository vì nó là repository , chứa data


### Câu 8. Một prototype bean `ExportJob` được inject trực tiếp vào singleton `ReportService`. Dev nghĩ mỗi lần gọi `reportService.export()` sẽ có `ExportJob` mới. Nhận định này đúng hay sai? Nếu sai, sửa bằng cách nào? `(5đ)`

**Trả lời:** không nha , vì là ReportService là singleton thì nó chỉ tạo duy nhất 1 instance từ nó thôi , nếu inject vào thì ReportService dược reference duy nhất 1 instance của exportjob , nếu muốn có instance mới thì dùng ObjectProvider<ExportJob> hoặc getObject trong export


### Câu 9. Có 2 bean `MomoPaymentGateway` và `VnpayPaymentGateway` cùng implement `PaymentGateway`. Nếu inject `PaymentGateway` vào constructor thì có thể lỗi gì? Hãy nêu cách dùng `@Primary` và `@Qualifier`. `(5đ)`

**Trả lời:** bị lỗi không biết chọn bean nào , dùng @Primary thì để set bean default còn muốn chỉ chi tiết thì là @Qualifier

## Phần III - Code mini `(1 câu × 10đ = 10đ)`

### Câu 10. Viết code mini gồm:

- `ExportJob` là prototype bean
- `ReportService` là singleton service
- `ReportService` dùng `ObjectProvider<ExportJob>` để lấy job mới mỗi lần gọi `export()`
- `StartupLogger` có `@PostConstruct` và `@PreDestroy`

`(10đ)`

**Trả lời:**

@Scope("prototype")
@Component
class ExportJob {
    void run() {
        System.out.println("exporting");
    }
}

@Service
class ReportService {
    private final ObjectProvider<ExportJob> exportJobs;

    ReportService(ObjectProvider<ExportJob> exportJobs) {
        this.exportJobs = exportJobs;
    }

    void export() {
        ExportJob job = exportJobs.getObject();
        job.run();
    }
}

@Component
class StartupLogger {
    @PostConstruct
    void init() {
        System.out.println("bean initialized");
    }

    @PreDestroy
    void destroy() {
        System.out.println("bean destroyed");
    }
}
