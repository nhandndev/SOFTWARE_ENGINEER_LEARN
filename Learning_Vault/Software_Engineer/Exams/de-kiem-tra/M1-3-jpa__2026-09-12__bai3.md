## Cau 1 - Transaction la gi? (3d)

**Tra loi:** transaction được coi là một đơn vị công việc trong database , coá nghĩa là nó sẽ 1 hoặc nhiều bước lại thành 1 đơn vị công việc , nếu 1 cái bị lỗi thì rollback làm lại từu đầu , nếu từ dầu đến cuối không lỗi gì thì là commit thành công hoàn thành transaction đó

## Cau 8 - Propagation REQUIRED (5d)

`Propagation.REQUIRED` nghia la gi? Neu method A co transaction goi method B cung `@Transactional(REQUIRED)` thi B dung transaction nao?

**Tra loi:**
Propagation trả lời được câu hỏi là đang có transaction A rồi thì lúc mà trong quá trình đó tạo ra transaction mới thì có dùng chung transsaction cũ k hay là new transaction mới , Propagation.Required là dùng để trả lời dùng tracsaction hiện tại . Nếu A có transaction gọi method B cũng Transactional(REQUIRED) thì B dùng tracsaction chung với A

## Cau 9 - Isolation nhan dien (5d)

Giai thich ngan:

- Dirty read.
- Non-repeatable read.
- Phantom read.

Co nen tu doi isolation lung tung khi moi hoc khong?

**Tra loi:** isolation là cách mà phân tách các transaction với nhau , ở đây là cách mà transaction đọc dữ liệu của nhau . Dirty read là đọc dơ , nghĩa là nó sẽ đọc luôn cả dữ liệu khi chưa commit , Non-reaptable read là đọc dữ liệu trên cùng 1 row nhưng mà value có thể sẽ khác nhau , ví dụ transaction A đọc row kia đang là 300 , B nó update thành 400 xong A đọc lại là thành 400 . Phantom read là có thêm row hoặc bớt row , ví dụ như transaction A đọc là có 10 row xong r B nó update thêm 1 nx là thành 11 xong A đọc lại là thành 11 . chính vì thế mà nó có các kĩ thuật để mà tăng khả năng nhất quán dữ liêu của các transaction nhưng mà phải trade off với hiệu năng / concurrency


## Cau 10 - Code mini (10d)

Viet pseudo-code cho `ProductService` gom:

- `create(CreateProductRequest request)` dung `@Transactional`.
- `getById(Long id)` dung `@Transactional(readOnly = true)`.
- `update(Long id, UpdateProductRequest request)` dung `@Transactional` va dirty checking.

Yeu cau:

- `create` check duplicate SKU, tim Category, save Product.
- `getById` findById, khong co thi throw `PRODUCT_NOT_FOUND`.
- `update` find Product, set name/price, map response, khong bat buoc goi save.

**Tra loi:**
Service
@RequiredArgsConstructor
public class ProductService {
    private final ProductRepository productRepository;
    private final CategoryRepository categoryRepository;

    @Transactional
    public ProductResponse create(CreateProductRequest request) {
        if (productRepository.existsBySku(request.getSku())) {
            throw new AppException(ErrorCode.DUPLICATE_SKU);
        }

        Category category = categoryRepository.findById(request.getCategoryId())
                .orElseThrow(() -> new AppException(ErrorCode.CATEGORY_NOT_FOUND));

        Product product = Product.builder()
                .sku(request.getSku())
                .name(request.getName())
                .price(request.getPrice())
                .category(category)
                .build();

        Product saved = productRepository.save(product);
        return toResponse(saved);
    }

    @Transactional(readOnly = true)
    public ProductResponse getById(Long id) {
        Product product = productRepository.findById(id)
                .orElseThrow(() -> new AppException(ErrorCode.PRODUCT_NOT_FOUND));

        return toResponse(product);
    }

    @Transactional
    public ProductResponse update(Long id, UpdateProductRequest request) {
        Product product = productRepository.findById(id)
                .orElseThrow(() -> new AppException(ErrorCode.PRODUCT_NOT_FOUND));

        product.setName(request.getName());
        product.setPrice(request.getPrice());

        return toResponse(product);
    }
}
